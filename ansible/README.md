# Deploying RedELK with Ansible

This is a thin remote-execution wrapper around `redelk.yml` and `./redelkctl`. It exists for one
reason: reaching many hosts. Everything it installs was generated by redelkctl from the single
configuration file in the repository root.

```
   redelk.yml                                    control node
       |
       | ./redelkctl generate
       v
   elkserver/.env, TLS material, cron files,     control node
   build/packages/<name>/ ...
       |
       |  ansible                     ansible
       +---------------------+------------------------+
       v                     v                        v
   repository copy       package for            package for
   + redelkctl install   c2server1              redir1
   (the RedELK server)   + sudo ./install.py    + sudo ./install.py
```

## What this playbook does

1. Runs `./redelkctl generate` **on the control node**, once, so every artefact and every per-host
   package exists (`redelk-generate` role).
2. Refuses to continue when an inventory host has no matching package - before any host is touched.
3. Installs Docker Engine on the RedELK server (`docker` role, optional).
4. Copies the repository to the RedELK server and runs `./redelkctl install` there
   (`redelk-server` role).
5. Copies `build/packages/<host>/` to every redirector and C2 server and runs `sudo ./install.py`
   there (`redelk-client` role).

## What it does not do

- **It does not configure RedELK.** There is no second set of variables for hostnames, C2 servers,
  attack scenarios, retention, alarms or credentials: those live in `redelk.yml` and nowhere else.
  If you want to change what RedELK does, edit `redelk.yml` and run the playbook again.
- **It renders no templates.** No `.env`, no `config.json`, no filebeat configuration, no cron
  files. redelkctl owns all of them, and the shell installers they used to come from are gone.
- **It does not create `redelk.yml` for you.** Run `./redelkctl init` first.
- **It does not delete anything on the server.** Files that disappear from the repository stay
  behind on the RedELK server; a redeploy never removes collected data.
- **It is optional.** `./redelkctl install` on the server plus copying one directory to each
  shipper does exactly the same thing by hand, and is the documented path for a handful of hosts.

## Prerequisites

On the control node:

- A configured `../redelk.yml` (`./redelkctl init`, then edit it).
- `ansible-core` 2.15 or newer, plus the collections in `collections.yml`.
- `rsync`, and Python 3.10+ for redelkctl.
- ssh access to every host, and `become` on every host. **Passwordless sudo is required** unless
  you log in as root: the repository is copied with `rsync`, which runs `sudo rsync` on the far end
  and cannot answer a password prompt.

On the targets:

- Debian or Ubuntu with apt. The generated `install.py` supports nothing else, and the `docker`
  role covers Ubuntu `focal`..`resolute` and Debian `bullseye`..`trixie`.
- Outbound network access: container images on the server, the Elastic apt repository on the
  shippers.

```bash
cd ansible
ansible-galaxy collection install -r collections.yml -p .ansible/collections
```

Host key checking is left alone on purpose. Populate `~/.ssh/known_hosts` first, or accept the
risk explicitly for a lab with `ANSIBLE_HOST_KEY_CHECKING=False`.

## The inventory must line up with redelk.yml

`./redelkctl generate` writes one package per host into `build/packages/<name>/`, where `<name>` is
the `name` field of a `c2_servers` or `redirectors` entry. **The inventory host name is what
selects that package.**

```yaml
# redelk.yml                       # ansible/inventory.yml
c2_servers:                        c2servers:
  - name: c2server1     <------->    hosts:
    type: sliver                       c2server1:
                                         ansible_host: 198.51.100.20
redirectors:                       redirs:
  - name: redir1        <------->    hosts:
    type: haproxy                      redir1:
                                         ansible_host: 198.51.100.30
```

If a host in `c2servers` or `redirs` has no package with its name, the run stops in the
`redelk-generate` role with a message listing the packages that do exist. When the two names cannot
be the same, set `redelk_package_name` on the inventory host instead.

Two groups are special:

- `elkservers` - exactly one host, and its name does not matter: it receives the repository, not a
  package.
- API-based C2 servers (`mythic`, `outflankc2`) are polled by the RedELK server and get no package
  at all. They belong in `redelk.yml` only - do not put them in the inventory.

## Usage

```bash
cd ansible
ansible-galaxy collection install -r collections.yml -p .ansible/collections

# 1. describe the deployment
$EDITOR ../redelk.yml
../redelkctl validate

# 2. describe how to reach it
$EDITOR inventory.yml

# 3. deploy everything
ansible-playbook -i inventory.yml playbook.yml
```

The first server run pulls several gigabytes of container images and then waits for the stack to
become healthy, which can take ten minutes or more. `redelkctl` prints its progress on the server,
not through Ansible, so the "Deploy RedELK with redelkctl" task simply sits there until it is done
and then shows the whole log at once.

Useful partial runs:

```bash
# only the server, only the shippers, only one host
ansible-playbook -i inventory.yml playbook.yml --limit elkservers
ansible-playbook -i inventory.yml playbook.yml --limit 'c2servers:redirs'
ansible-playbook -i inventory.yml playbook.yml --limit redir1

# deploy what is already in build/packages/ without running redelkctl generate
ansible-playbook -i inventory.yml playbook.yml --skip-tags generate

# add a redirector to an existing deployment: add it to redelk.yml and the inventory, then
ansible-playbook -i inventory.yml playbook.yml --limit redir2

# pull the newest container images while redeploying the server
ansible-playbook -i inventory.yml playbook.yml --limit elkservers \
  -e '{"redelk_install_args": ["--pull"]}'
```

Tags: `generate`, `docker`, `server`, `client`.

For a real deployment, start from `inventory-live.example.yml`.

## Variables

Only the variables below exist, and all of them are about reaching hosts. Everything else comes
from `redelk.yml`.

| Variable | Default | Where |
| --- | --- | --- |
| `redelk_repo_path` | `{{ playbook_dir \| dirname }}` | `group_vars/all.yml` |
| `redelk_config_file` | `redelk.yml` | `group_vars/all.yml` |
| `redelk_packages_path` | `{{ redelk_repo_path }}/build/packages` | `group_vars/all.yml` |
| `redelk_remote_base_path` | `/opt/redelk` | `group_vars/all.yml` |
| `redelk_generate` | `true` | `redelk-generate` role |
| `redelk_install_docker` | `true` | `group_vars/elkservers.yml` |
| `redelk_install_args` | `[]` | `group_vars/elkservers.yml` |
| `redelk_server_run_install` | `true` | `redelk-server` role |
| `redelk_package_name` | `{{ inventory_hostname }}` | `group_vars/{c2servers,redirs}.yml` |
| `redelk_client_install_args` | `[]` | `group_vars/{c2servers,redirs}.yml` |
| `redelk_client_force_install` | `false` | `redelk-client` role |

Each role's `defaults/main.yml` and `README.md` document the rest, including which parts of the
repository are copied to the server and which paths a redeploy must never overwrite.

## Roles

| Role | Runs on | Does |
| --- | --- | --- |
| [`redelk-generate`](roles/redelk-generate/README.md) | control node | `./redelkctl generate`, and checks the inventory against it |
| [`docker`](roles/docker/README.md) | RedELK server | Docker Engine + Compose v2 from Docker's apt repository |
| [`redelk-server`](roles/redelk-server/README.md) | RedELK server | copies the repository, runs `./redelkctl install` |
| [`redelk-client`](roles/redelk-client/README.md) | redirectors, C2 servers | copies `build/packages/<host>/`, runs `sudo ./install.py` |

## Testing

Both scenarios need a working local Docker daemon and the ability to run privileged containers.
They are also run by the `Molecule` workflow whenever `ansible/**` changes.

```bash
cd ansible
ansible-galaxy collection install -r molecule/docker/collections.yml -p .ansible/collections
molecule test -s docker     # the docker role, on Ubuntu and on Debian

ansible-galaxy collection install -r molecule/redelk/collections.yml -p .ansible/collections
molecule test -s redelk     # the whole playbook, against three containers
```

The `redelk` scenario copies the repository into molecule's ephemeral directory, drops
`molecule/redelk/files/redelk.yml` on top of it and works there, so it never touches your own
`redelk.yml`, certificates or packages. Its converge step imports `playbook.yml` itself. Two things
are deliberately out of scope, because they need Docker in Docker and an exact Elastic build:

- the server converges with `redelk_server_run_install: false`, and verify runs
  `./redelkctl validate` on the server instead;
- the shippers install with `--no-filebeat`, so everything except the filebeat package is exercised.

## After the run

```bash
ssh <redelk-server>
cd /opt/redelk
./redelkctl doctor      # checks containers, Elasticsearch, Kibana, ingest and certificates
./redelkctl secrets     # the generated credentials
./redelkctl logs -f     # container logs
```

`./redelkctl doctor` on the server is the authority on whether a deployment works - a green
Ansible run only means the files arrived and the installers exited zero.
